# 1. Mission

Increase qualified organic inquiries for Kingdom Design House by improving four owned-site systems and one external authority system:

| Growth Area | Weight | Execution Owner |
|---|---:|---|
| High-intent Web + AI landing pages | 25% | Development / Content |
| Citation-worthy content, tools and case studies | 20% | Development / Content |
| Conversion optimization + Jarvis | 10% | Development |
| Technical SEO / schema / indexing / monitoring | 10% | Development |
| Authority / backlinks / reviews / brand mentions | 35% | Business Development / Marketing |

The development environment is responsible for approximately **65%** of this strategy.

The remaining **35% cannot be manufactured in code**. It requires genuine third-party references, authentic customer feedback, editorial coverage, partnerships, memberships and useful contributions to external organizations.

Primary objective:

> Turn Kingdom Design House from a visually strong service website into a recognized Long Island Web + AI business entity that search engines, AI search systems and prospective customers have multiple independent reasons to trust.

# 4. Development Rules

All implementation work must follow these rules.

1. Preserve existing production URLs wherever practical.
2. Do not fabricate clients, testimonials, reviews, results, awards or certifications.
3. Do not invent physical offices.
4. Do not create doorway-style city pages.
5. Do not keyword-stuff Long Island, Freeport or NYC.
6. Do not create schema representing facts that are not visible and accurate.
7. Do not count CTA clicks as qualified leads.
8. Do not count Jarvis opens as qualified leads.
9. Do not publish AI-generated statistics without a verifiable source.
10. Do not replace useful existing content merely for freshness.
11. Preserve the KDH visual identity.
12. Improve semantic HTML without sacrificing the current typography treatment.
13. Major indexable content must be available in the rendered HTML and not depend exclusively on animation or client-side interaction.
14. All client-result claims must have an internal evidence source and approval status.
15. Every new page must map to a distinct buyer intent.

```text
USER

That may be a good candidate for a controlled knowledge
assistant if the answers come from approved documentation.

I'd first check:

1. Where the approved answers currently live
2. Whether answers change frequently
3. Which questions require a human
4. Whether customer information is involved
5. Whether answers need to be written back to another system
```

Only after providing useful guidance:

```text
Would you like KDH to map this workflow and recommend
an MVP approach?
```

Then request contact details.
